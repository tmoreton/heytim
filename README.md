# HeyTim

One monorepo for HeyTim's native AI friends app, public website, reviewed skills, API and
AgentCore runtime. The Expo application has been archived outside the repository;
it is no longer a build or release target.

## Structure

```text
apps/
  iOS/                         Shared SwiftUI iPhone + macOS app
  website/                     Vite + React marketing site and skills library
services/
  API/                         Amplify application backend and API contract
  runtime/                     AgentCore Python runtime, tools and evaluations
catalog/                       Reviewed bots, skills, tool schemas and validation
packages/
  heytim-contract/             Generated TypeScript route contract and tests
  heytim-transcription/        Native Swift transcription core
agentcore/                     Declarative AWS resources and deployment wrapper
```

These are component boundaries within one product. `tmoreton/heytim` is the
canonical source and publishing repository. See the
[repository and licensing model](docs/repository-and-licensing.md).

`apps/iOS` builds **both iOS and macOS**. There is no public browser chat. The
website's `/app` and `/invite` routes help people open the installed Apple app.
The backend's existing users, data, and AWS resource identities remain stable
through the brand change. The public website and bot catalog live at `heytim.ai`.

## Local development

Use Node 22.23.2, Python 3.14, `uv`, and Xcode with the installed iOS simulator.

```sh
# iPhone or Mac
./scripts/apple-app.sh run ios
./scripts/apple-app.sh run macos

# Public website, with no cloud credentials required
npm ci --prefix apps/website
npm run dev --prefix apps/website

# Server dependencies
npm ci --prefix services/API
npm ci --prefix agentcore/cdk
uv sync --project services/runtime --frozen
```

The native speech model and frameworks are prepared and checksum-verified by
`packages/heytim-transcription/scripts/prepare-apple.sh`. These large generated
assets are intentionally not committed.

## Verify

```sh
./scripts/verify.sh application  # Vite build, library behavior, catalog, contracts
./scripts/verify.sh server       # API, runtime, AgentCore schema and wrapper
./scripts/verify.sh apple        # Speech tests, macOS tests, iPhone UI tests
./scripts/verify.sh all
```

The website build prerenders every public page and publishes only the public
catalog allowlist. It tests that chat, auth and Expo dependencies cannot leak into
the bundle. Catalog instructions remain versioned; existing installed versions
are not changed by this migration.

## Releases

- A push to `main` runs affected checks on the Mac mini. It does not deploy.
- AWS production releases remain manually triggered through the protected
  production workflow. See [the release guide](docs/production-release.md).
- Apple-only releases can be built and uploaded locally, without GitHub Actions:

  ```sh
  APPLE_TEAM_ID=GVXC5FQ2RP ./scripts/apple-app.sh testflight all
  ```

  Configure the three `APP_STORE_CONNECT_*` variables documented by the script.
  Signing keys remain outside Git. Preflight checks require committed source and
  production client configuration; the script runs native tests before upload.
- The [Pages workflow](.github/workflows/pages.yml) publishes `heytim.ai`
  directly from this repository. The website's [publish script](scripts/deploy-website.sh)
  verifies the release and queues that workflow.

`services/API/amplify_outputs.json` is the public configuration generated by
Amplify. `npm run outputs:apple --prefix services/API` copies only the native
client fields into the app. The marketing website does not consume it.

## Working safely

AgentCore JSON is authoritative. Keep resource names stable, read the matching
schema before changing config, and run `agentcore validate`. Directory cleanup
must never recreate live users, memories or storage. Backend authorization and
tool approval remain server-enforced. Skills are reviewed instructions, never
downloaded executable code or credentials.

The Expo reference archive is at
an offline maintainer-controlled location. Original history also remains in Git.
The imported catalog began from public commit `62a1f53`; verified local bundles
preserve the retired repositories. See
[migration notes](docs/monorepo-migration.md).
