## Draft angles to test

These are proposed opinions, not claims about Tim's past results:

- “A coding agent opening a PR is the easy part. Knowing when it's safe to merge is the product.”
- “I want AI bots I can reuse across work and side projects. The context should change. The whole bot shouldn't have to.”
- “Build in public gets more useful when you show the tradeoff, not just the launch screenshot.”
- “A morning AI report should leave me with three things to do. If it leaves me with thirty tabs, it missed the point.”
- “The most useful agent demo isn't a perfect run. It's what happens when a tool fails halfway through.”

Tutorial candidates: build a reusable social research team; take a coding agent from repository access to a reviewed PR; demonstrate failure recovery and separate personal/work memory in Strands. Each needs fresh evidence and a working demonstration before publishing.

## Strands work research

Use [Strands](https://strandsagents.com/) and its official repositories as the baseline. Check current documentation and releases for LangGraph, CrewAI, Google ADK, Microsoft Agent Framework and OpenAI Agents SDK before making comparisons. Compare concrete tasks: tool integration, state, evals, deployment and recovery. The most useful marketing output is a tutorial that answers a real developer question, with reproducible code and candid tradeoffs.
